# Passive blueprint overlay — Android source candidate (2026-10-13)

A user starts a real `TYPE_APPLICATION_OVERLAY` via **Blueprints → Overlay**, after manually granting Android Draw Over Other Apps. A `specialUse` foreground service holds a visible notification with **Stop Overlay**. Starting happens from the foreground app, never on boot. The service holds an immutable JSON snapshot of the saved mechanic, generated with the same `BlueprintGenerator` used by the in-app guide. It runs no simulator, polls no files and accesses no Fortnite data.

The FN bubble can be dragged, expanded to a compact panel, or collapsed; the overlay contains Steps, Links and a zoom/pan Graph. Bubble/panel coordinates, selected mechanic and step/checklist state are stored locally. The window fits updated display bounds on configuration changes. Both expanded and collapsed windows receive touches only within their own window rectangles, via `FLAG_NOT_FOCUSABLE` + `FLAG_NOT_TOUCH_MODAL`. The stop action removes the view and foreground service. If Android kills the service, the user launches it again deliberately; there is no restart loop.

Android 14+ requires manifest `FOREGROUND_SERVICE_SPECIAL_USE`, subtype declaration and the correct service flag. Android 15+ removes the broad background-FGS exemption for overlay permission unless a visible overlay is already present; start this service through the visible Activity. Some OEMs, battery management, anti-cheat/game policies and apps using Android `HIDE_OVERLAY_WINDOWS` may prevent drawing above Fortnite even after permission. This is not overridable and **requires real-device Fortnite testing**. No accessibility, screenshot, touch injection, root, network, or game-process integration is used.

Manual checks: permission denied/allowed, expanded/collapsed in portrait and landscape, pinch and pan, touch pass-through outside bounds, all notification Stop routes, switching blueprints, game background and app return, process death/relaunch, device-specific game overlay visibility, and Android signing continuity.

## Landscape usability follow-up — 2026-10-13

Real owner-phone evidence confirmed FN overlay visibility above Fortnite and usable Steps, Devices and Links pages in the first CI-passing overlay release (Android run 38435563960, source commit 6efa671). The graph was blank and the panel too large. The next candidate changes only overlay presentation/drawing: landscape starts at 52% screen width × 52% screen height (about 27% of the screen), portrait at 88% × 44%; panel Size controls adjust width/height using screen percentages, remembered separately for landscape and portrait. A reset button restores compact defaults. Bubble and panel positions are also orientation-specific, clamped to visible bounds.

The Tabs − / Tabs + toolbar action hides/reveals the four navigation tabs without changing the current tab. The active Steps or Graph remains in view, and compact notes are hidden behind an explicit Show verification notes action. Graph uses pixel-correct fit, zoom around pinch focus, panning and an explicit Fit graph control. No idle draws, simulations, polling, game data or injection are introduced. The newer code is **not yet CI- or phone-certified**. Recheck landscape layout, graph rendering, sliders, rotation, outside-touch pass-through, collapse/reopen, and Stop in the next APK.

## Connections and folders UX candidate — 2026-10-13

Android run `38441055829` certified the compact overlay source at `ac754adf`; later owner phone evidence shows the compact overlay graph draws correctly over Fortnite; size sliders, tabs and node wires were visible. The next unverified candidate retains **Steps**, changes **Links** into a device explorer, and keeps **Graph** as the uncluttered actual device layout. One tap on a graph node opens its saved configurations plus the exact incoming/outgoing direct Event → Function connections. A long press temporarily dims all cards except the focused node and its direct neighbors; only directly incident wires remain highlighted. Double-tapping blank graph area clears focus. This is presentation only: all devices remain selectable, and no game or simulator signals are issued.

In Links, tap a device to see sends/receives; **Group direct connections** shows a selection preview of ungrouped one-hop neighbors before creating a named organizational folder. Saved folders may be renamed or ungrouped without removing their devices. An editable folder name temporarily enables keyboard focus on this overlay window; on Save/Cancel/tab exit/collapse, it restores `FLAG_NOT_FOCUSABLE` and hides the keyboard. Creation, rename and ungroup explicitly write the current saved mechanic to Room and refresh the overlay snapshot; there is no idle database polling. The same optional `folders` field travels in format-2 `.c1logic` documents, and duplicates/missing IDs are rejected by the existing graph codec. The Room schema remains version 1. A folder is **never** a visual or executable graph node.

Phone checks after CI: 1) focus one node, verify only its immediate neighbors remain bright; 2) verify dimmed nodes still respond to taps/long press; 3) clear via double-tap empty canvas; 4) view a node's options/port directions; 5) group, name, rename, ungroup; 6) collapse/reopen, return to app, edit/save and export/reimport, confirming groups survive; 7) type and close the naming editor and confirm Fortnite receives touches outside the window again. The candidate has not yet passed CI or phone acceptance.

## Cover Flow workspace layout (CI/phone candidate, 2026-10-13)

The expanded panel now dedicates its interior to exactly one of Graph, Steps or Links. The graph draws edge to edge, with a small grab handle, Fit control and contextual `⋯` options layered above it; its tap-to-inspect sheet temporarily overlays the lower region instead of changing graph zoom or shrink-fitting nodes. Steps/checklist and Links/folder editing remain scrollable full-panel views. The old rectangular in-panel toolbar and navigation row are gone.

A **second, small `TYPE_APPLICATION_OVERLAY` WindowManager window** carries only a transparent three-card Cover Flow navigator centered just below the panel. Each card is individually drawn and accessible, arranged with 3D inward perspective, and opens its view on tap; swiping left/right across a card rotates between destinations. The selected tab is remembered per mechanic. Both system overlay windows are `FLAG_NOT_FOCUSABLE | FLAG_NOT_TOUCH_MODAL` except during intentional folder-name entry on the main panel. Their bounds are explicit; no full-screen transparent input surface is used. The navigator follows panel dragging and size/orientation changes and disappears on collapse, Stop or Hide navigation. The panel position is clamped to reserve room for the navigator underneath it; maximum adjustable height is limited accordingly. Touches outside both window rectangles belong to Fortnite.

Open the compact `⋯` menu for Size (separate width/height sliders, compact reset), Hide/Show navigation, Collapse to FN, or Stop. Persistent Stop notification remains available. No new Android permissions, foreground threads, polling, gameplay integration or continuous redraw/animation are introduced. As with every two-window Android overlay, actual Fortnite/OEM rendering and interaction must be verified on the owner's phone after successful Android CI.

Phone acceptance: launch overlay in Fortnite, confirm carousel is below rather than within the dark panel; tap/swipe all three destinations; drag panel and ensure carousel follows; verify full-height graph and selected-node inspector, focus/double-tap clear and Fit; adjust size, hide/reveal navigation; collapse/reopen; rotate; test Fortnite controls outside both actual overlay windows; stop from menu and persistent notification.

If the second navigator window cannot be created, the main panel stays active and the `⋯` menu offers a **View Steps / View Links / View Graph** fallback. The original single bubble/panel feature is never deliberately torn down for a navigator-only failure.

## Inline node expansion (Android CI pending)

Graph no longer creates a separate settings bottom sheet. Tapping a device draws a larger version of that device at the same saved graph coordinates, including wrapped options, builder notes and exact incoming/outgoing binding labels. Tap again to collapse; other device taps change selection. Large device configurations are scrolled inside the card (not with the graph pan gesture), and the camera adjusts only enough to keep the card readable in the current overlay size. One-hop long-press focus, blank double-tap focus clear, Fit/pinch/drag, Steps/Links, folder metadata and Cover Flow persist. Node sizes are view-only. Source baseline is CI-green `5d15dc96` and new Android acceptance is pending.
